# Catch-photo snap eval — 2026-08-27 (285-photo corpus)

Second labeling round over every catch photo on Noah's phone (285 photos,
2026-05-19 → 2026-08-27; the July round's 63 labels carried over). Noah
click-labeled the true plane position per photo (`labels-2026-08.json` —
`{x,y}` in upright saved-photo pixels, or `none`/`unsure`). Joined per catch
to the SwiftData row (`photoFocus` = baked bracket center) and to
`catch_photo_snap` telemetry (outcome + correction_pt).

Harness (uncommitted, local): `~/code/tailspot_utils/snap-tuning-2026-08/` —
`label_server.py` (click-to-label UI), `sweep.py` (offline detector passes:
shipped fine ring + shipped coarse + full-frame native tiles, all at conf
0.10 so gate variants replay offline), `analyze.py`, `build_review_doc.py`.
Caveat: offline runs on the SAVED photo (3072-cap, re-encoded) while the app
searches the raw ~12 MP still, so offline recall slightly understates the
app's.

## Results

- **Precision when snapped: 32/34 verified on-plane**, bracket 1–6 px from
  the label. The gates from the July eval (conf ≥ 0.25, side ≤ ⅓ crop) are
  confirmed at 4× the corpus size — floor changes to 0.15/0.20 add mostly
  wrong snaps (+4 right / +14 wrong at 0.15).
- **Fallback (77% of catches; 85% fleet-wide) is model capability, not
  gates**: full-frame sweep at conf 0.10 sees the labeled plane in 2/89
  fallback photos. Fallback catches: median 12 km slant, ~13 px expected
  footprint (vs 4.3 km / 26 px for snapped) — below the detector floor.
  Median zoom is 1.0× in both groups → zoom is the recall lever (parked:
  auto-zoom nudge idea).
- **Every verifiable bad snap was a wrong object at correction ≥ 207 pt**
  (streetlight head, bare twig tip, parked airport tail); every
  verified-correct snap corrected ≤ 147 pt (≈ 248 ref px). Fleet telemetry:
  50/604 snaps ≥ 200 pt — the same class.
- **Rejected:** footprint-consistency gates (expected px from wingspan/slant
  vs det size) — they kill 10/11 replay-wrongs but ~20% of correct snaps
  too; the detector legitimately finds planes far below the naive expected
  size (median correct snap expectation: 15 px). Wider radii (1000–1400)
  add zero correct snaps.

## Change shipped from this eval

`CatchPhotoSnapper.maxSnapRadiusPixels` 700 → **300** ref px (~175 screen pt)
and `centerAcceptRadiusPixels` 340 → 150 (same ½ proportion). Splits the
correct (≤ 248 ref px) and wrong-object (≥ 350 ref px) correction
populations with margin. Offline cost: 1 of 55 replay-correct snaps. The
July 609-px verified correction that justified 700 predates exposure-time
re-projection, which now absorbs that drift class.
