Challenges phase 2: the entry points

branch feat/challenges-client · 2026-09-15 · hosted-window snapshots with a fixture-backed ChallengesModel injected

The screens themselves are reviewed in 2026-09-15-challenges-phase2-screens.html (33 states). This doc covers the three places Challenges appears on existing screens, plus what the app does at launch.

Behaviours

  • Launch and foreground: TailspotApp owns one ChallengesModel (real client, real reminder scheduler), injects it into the environment, and on every foreground refreshes the config, then the list when the verdict is available. The list refresh re-plans the local reminders.
  • Kill switch: config enabled: false hides the tile, flag and strip; the hub (if already open) says "Challenges aren't available right now".
  • Older build: config minBuild above this build → the hub shows "Update Tailspot to keep using Challenges" with the App Store link. DEBUG builds pass Int.max so a local deploy never trips it.
  • Headline priority: live › unseen results › upcoming › none, shared by the tile and the strip through one pure copy function (tested for every case).
