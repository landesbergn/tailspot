Challenges phase 0: Leaders on the bar, account top right

branch feat/challenges-nav · 2026-09-15 · client only · opens the v1.2 train (MARKETING_VERSION 1.2.0)

The first of the Challenges phases changes only navigation. The leaderboard was two taps deep (Profile → Leaders) for a destination people open a lot; it is now the bottom-right bar button. The Profile moved to a 44 pt account button top right. Nothing behind either surface changed. Spec: docs/reviews/2026-09-15-challenges-v1-spec.html on feat/challenges-poc, section 3.

What changed in code

  • One enum, one sheet. showHangar and showProfile became primarySheet: PrimarySheet? (PrimarySheet.swift) driving a single .sheet(item:) and a single .onChange. ContentView.body is at the compiler's type-check budget, so a third surface had to cost zero chain links; this costs minus two. Every "is a sheet up?" gate (camera occlusion choreography, trophy and restore overlays, the streak ask, the review prompt) reads primarySheet == nil, so Leaders inherits exactly the Hangar/Profile behaviour: camera stops behind the opaque wash, trophies re-diff on dismiss.
  • LeadersSheet wraps LeaderboardScreen in a NavigationStack with Done. The screen itself is untouched; leaderboard_viewed still fires on appear, so the uplift from one-tap access shows up in the existing event.
  • Compass banner inset 16 → 60 pt so the centred, content-sized badge wraps at accessibility sizes instead of sliding under the account button.
  • Profile keeps its Map / Leaders tiles until phase 2 replaces Leaders with Challenges; a lone Map tile would look like a bug.
