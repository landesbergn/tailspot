Measured as zero-catch → first-catch activation rising from the 44% post-GA baseline.
  • Product authority: Noah's calls in the 2026-08-27 brainstorm dialogue (audience, direction, weekly-board ending), on top of the 2026-08-17 Flight Plan board verdicts. The first-catch activation slice (R4/R5 of docs/plans/2026-08-17-1443-feat-v1-1-release-scope-plan.md) slipped v1.1, which was submitted for review 2026-08-26; this plan supersedes and deepens that slice for the v1.2 realm.

Product Contract

Summary

A guided first-catch mode for any user with zero catches: the viewfinder actively steers them to the nearest catchable plane, coaches the center-and-capture mechanic with a visually loud capture affordance, and says so honestly when the sky is quiet. The first catch runs the full existing loop — reveal, route guess, First Catch trophy — and lands on a new "your place this week" moment on the existing weekly leaderboard.

Problem Frame

Since GA (2026-08-08), 66 new people opened the app and only 29 ever caught a plane. The old assumption — that the onboarding flow was the leak — is dead: 94% finish the three-step onboarding, ~95% grant both permissions, and the AR view starts for 61 of 66. The funnel breaks after that, in two places.

Leak 1 — 21 users had a catchable plane nearby and never caught (32% of all new users). Decomposed per person: 9 never touched the screen again, 11 fired only miss events (6 tapped empty sky — one hunted across 3 sessions with 40 empty-sky taps and never landed on a plane; 5 saw only the compass-error caution), and exactly 1 was ever denied by a gate (a grounded-plane tap). Zero of the 21 ever successfully tapped a plane label. Nine of them returned for 2–4 sessions and still stalled. The catch gates are not the problem; reaching a plane is.

Leak 2 — 11 users got a working AR view and never had a plane in range, the quiet-sky and coverage problem.

Three verified mechanics explain leak 1. Catching requires aim — the plane must sit in a tight central catch zone (lone-plane-on-frame and tap-pin are the only exceptions) — and nothing teaches that. The capture button's only "you can catch now" signal is an opacity change from 0.4 to 1.0. And nothing steers the user toward a plane that is in range but off-frame, which first_plane_seen proves is common: it fires for planes the user may never have had on screen at all.

Key Decisions

KD1 — The trigger is zero catches, not first launch. (session-settled: user-directed — chosen over fresh-installs-only and over adding a re-engagement nudge: keying off "no catches yet" reaches the 37 existing never-activated users on their next session without expanding scope into notifications.)

Governs R1.

KD2 — Guidance is live coaching on the real sky, not a canned tutorial, quest card, or relaxed catch rule. (session-settled: user-approved — chosen over a persistent quest checklist (viewfinder clutter), a radar-orientation-first flow (a screen before the fun), and first-catch aim relaxation (undercuts the earned catch): in-viewfinder steering attacks the verified aim gap directly.)

Governs R2, R3, R4.

KD3 — Simulated first catch stays parked. (session-settled: user-directed — 2026-08-17 Flight Plan board verdict, reaffirmed here: teaching happens only on real planes; a fake catch would spend the first-catch moment on something that isn't real.)
KD4 — The first-catch payoff lands on the weekly leaderboard window. (session-settled: user-directed — chosen over the all-time board: a board that reset this week is climbable for someone with one catch. The weekly window already shipped, so this is a landing moment, not a dependency.)

Governs R8.

KD5 — When the compass is bad, guidance degrades honestly instead of mis-steering. (session-settled: user-approved — 5 of the 21 stalled users saw only the compass caution; steering arrows on a bad heading would point at empty sky and teach distrust.)

Governs R5.

Requirements

Guided catch mode

IDRequirement
R1.The guided first-catch experience is active for any user with zero catches — fresh installs and existing users alike — and retires permanently once their first catch lands.
R2.When a catchable plane is in range but not in frame, the viewfinder steers the user toward it: which way to turn, roughly how far away it is, and what it is.
R3.Coaching names the current mechanic one step at a time — find the plane, center it, capture — advancing on the user's actual state rather than on a timer.
R4.The capture affordance becomes visually loud (a pulse or equivalent) the moment a catch is possible, replacing the current opacity-only signal.
R5.When heading accuracy is poor, guidance stops steering and says so — prompting calibration — rather than pointing arrows on a heading it can't trust. Per KD5.

Quiet sky

IDRequirement
R6.When nothing catchable is in range, the guided experience says so honestly — the sky is quiet, the app is not broken — and sets an expectation for when to try again, without promising traffic it can't predict.

Completing the loop

IDRequirement
R7.The first catch runs the full existing loop unchanged: the reveal card, the route-guess bonus round, and the First Catch trophy.
R8.After the first-catch celebration completes, the user is shown their place on the THIS WEEK leaderboard window. Per KD4.

Measurement

IDRequirement
R9.Telemetry can tell whether this worked: events distinguish "a plane label actually rendered on screen" and "the user tapped a visible label" — the two gaps that currently make the 21 stalled users unexplainable. Existing event semantics are preserved.

Key Flows

F1. Zero-catch user, plane in range — Trigger: a zero-catch user opens the viewfinder with a catchable plane nearby.
Steps: steering points them to the plane (R2) → coaching advances as they find and center it (R3) → the capture affordance goes loud (R4) → catch → reveal, route guess, First Catch trophy (R7) → their place on this week's leaderboard (R8). The mode retires (R1).
Covers: R1, R2, R3, R4, R7, R8.

F2. Zero-catch user, quiet sky — Trigger: a zero-catch user opens the viewfinder with nothing catchable in range.
Steps: the honest quiet-sky state explains that the app works and the sky is quiet, and sets a return expectation (R6). Next session with traffic, F1 runs.
Covers: R1, R6.

F3. Bad compass during guidance — Trigger: heading accuracy degrades while F1 is steering.
Steps: steering stops, the experience says the compass needs calibrating and how (R5); steering resumes when the heading recovers.
Covers: R5.

Acceptance Examples

  • AE1. Covers R1. Given one of the 37 existing zero-catch users updates and opens the app, the guided experience is active. Given a user with one catch, nothing from this plan appears.
  • AE2. Covers R2. Given a catchable plane 4 km away behind the user, the viewfinder tells them which way to turn before any label is on screen.
  • AE3. Covers R4. Given a plane enters the catch zone, the capture affordance visibly changes beyond opacity; given the zone empties (and no lone-plane or pinned exception applies), it returns to quiet.
  • AE4. Covers R5. Given heading accuracy is poor, no directional steering is shown — the calibration prompt is, and steering returns when accuracy recovers.
  • AE5. Covers R6. Given no catchable traffic in range, the user sees the quiet-sky state rather than an empty viewfinder; it does not claim traffic is coming at any specific time.
  • AE6. Covers R8. Given the first catch's celebration finishes, the user sees their rank on the THIS WEEK window — not the all-time board.
  • AE7. Covers R9. Given a labeled plane renders on screen and the user never taps it, the funnel can now distinguish that user from one whose plane never appeared on screen.

Success Criteria

  • Zero-catch → first-catch activation for new users rises from the 44% baseline (66 → 29 since GA). Directional target: ~60%, to be re-baselined once R9's events land.
  • The "plane nearby but never caught" cohort (32% of new users today) shrinks, measured with R9's new events rather than the ambiguous first_plane_seen.
  • Median first-open → first-catch stays in the ~10-minute band for users with traffic in range.

Scope Boundaries

  • The three-step onboarding (welcome → permissions → handle) is untouched — the data cleared it as a leak.
  • No quest/checklist card, no first-catch aim-gate relaxation, no simulated first catch (KD2, KD3).
  • No re-engagement notifications for lapsed zero-catch users — the mode reaches them only when they return on their own.
  • The leaderboard itself is unchanged; this plan adds only the first-catch landing moment on the existing weekly window.
  • Coverage itself (why leak 2's skies are quiet) is separate work — the FAA SWIM spike and backend coverage options live outside this plan.

Dependencies / Assumptions

  • The weekly leaderboard window is live end-to-end (backend/src/routes/leaderboard.ts serves window=week; the app has a window switcher) — verified 2026-08-27.
  • The route-guess round, First Catch trophy, and reveal are shipped surfaces this plan orchestrates, not builds.
  • Funnel figures are the 2026-08-27 PostHog pull (66 new persons since GA; small-cohort caveats apply; Noah excluded).
  • v1.1 (streaks, submitted for review 2026-08-26) ships before this; this plan targets the v1.2 realm.
